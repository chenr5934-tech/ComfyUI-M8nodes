# M8 · 测试分工与实机清单

> 这份文件回答两个问题：**谁跑什么**，以及**跑出问题怎么回报**。

---

## 一、分工（硬规矩）

| 谁来跑 | 跑什么 |
| --- | --- |
| **助手（AI）** | `python tests/smoke_import.py`：脱离 ComfyUI 的静态验证。不联网、不启动服务、不碰你的实例 |
| **项目所有者（人）** | 一切需要 ComfyUI 实机、浏览器界面、真实 API 调用的验证 |

**助手不做的事**：

- 不启动 ComfyUI，不重启你正在用的实例
- 不替你点节点、不替你填密钥、不替你发真实请求
- 不声称「已经测过」任何它没跑过的东西

**为什么这么分**：ComfyUI 实例是你在用的工作环境，里面有你的工作流和显存状态。
助手在旁边起第二个实例会有端口、缓存、显存、`user/` 目录的互相干扰，
而节点的真实表现（界面渲染、连线、执行）本来也只有你能看见。

## 二、静态验证（助手负责，随时可跑；两个脚本都要跑）

```bash
python tests/smoke_import.py      # 插件加载、节点契约、错误码、路由表
python tests/verify_assets.py     # 前端资源文件都在、音效齐全
node tests/syntax_check.js        # 所有前端 js 按 ES module 解析一遍（不执行）
node tests/frontend_setup.js      # 真的把每个节点的 setup() 跑一遍
node tests/frontend_webapp.js     # M8web 外壳：主题、侧栏、顶栏、跨页契约
                                  # 另外还查接线：js 用的 id 在页面上存不存在、
                                  # js 用到的模块有没有被加载、用到的类有没有样式

# 每个功能一个套件，改了哪个跑哪个；动到公共层（app.js / shell.css / studio.js）就全跑
node tests/frontend_cut.js        # 图片工坊 · 分段裁剪
node tests/frontend_mask.js       # 图片工坊 · 分段遮挡
node tests/frontend_sticker.js    # 图片工坊 · 贴纸遮挡
node tests/frontend_grid.js       # 图片工坊 · 宫格拼图
node tests/frontend_paint.js      # 图片工坊 · 文字与画笔
node tests/frontend_oc.js         # OC 工坊
node tests/frontend_meta.js       # 图片元数据
node tests/frontend_lora.js       # LoRA 解析
node tests/frontend_prompts.js    # 提示词归纳
node tests/frontend_obfuscate.js  # 混淆图
node tests/frontend_pixel.js      # 像素风转化
node tests/frontend_backup.js     # 备份导出 / 导入（三条数据线同一套）
node tests/frontend_migrate.js    # 旧 IndexedDB 数据搬进 M8data

# 这个不是「实跑」，是契约：规则在 Python 和 JS 里各写了一遍，
# 用例只有一份（tests/mmproj_cases.json），两边跑同一批
node tests/frontend_mmproj.js     # 主模型 ↔ mmproj 自动配对

# 写前端之前不是跑它，而是**问它**：这个类名/API 在 ComfyUI 里真的存在吗
python tests/check_comfy_selectors.py .comfyui-body-top
```

覆盖的东西：插件能否按 ComfyUI 的方式加载、节点契约、路由表、
前后端硬编码字符串是否一致、错误码与报错手册是否对得上、纯函数逻辑。

输出 `OK` 就是全过。**这只是入场券，不代表插件在界面里能用。**

`frontend_setup.js` 单独说一句：它造一套最小 DOM 桩，**真的把每个节点的 `setup()`
执行一遍**。存在的理由是有一类错误语法检查完全放行 —— 比如引用了作用域外的变量，
`node --check` 一路绿灯，但鼠标一按就 ReferenceError。这个坑实际踩过
（多角色编辑的画布「拖不动」，根因是 `pointerdown` 里引用了不存在的变量）。
所以凡是**改了前端节点的初始化或事件绑定**，这一条必须跑。

## 三、实机清单（所有者负责）

### 大模型推理节点 · 参数不能丢

- [ ] 建一个推理节点，把**温度改成 0.7、max_tokens 改成 2048、超时改成 300**
- [ ] **重启 ComfyUI**，重新打开工作流 → 三个值还是你设的那个（不是 NaN / 0）
- [ ] 保存工作流、清空画布、再载入 → 值同样不变
- [ ] 节点上的控件顺序是：**先是参数**（供应商 / 地址 / 密钥 / 模型 / 提示词 / 思考 / 温度…），**按钮全在最后**

### 小鲸鱼 · 让它自己跑图

这几项要真的动到画布，请在**一个可以随便折腾的工作流**上试，别拿正在用的。

- [ ] 对话里问「队列里现在有什么」→ 它调 get_queue，对话里出现【看队列】和结果
- [ ] 对话里说「把节点 3 的 steps 改成 10」→ 画布上那个节点的值真的变了
- [ ] 改完之后它有没有说清「改了哪个节点的哪个参数、从什么变成什么」
- [ ] 说「把种子改成 999」但**没给节点编号** → 它应该先问清楚，而不是随便挑一个节点改
- [ ] 对话里说「跑一张」→ 它调 queue_prompt，ComfyUI 的队列里真的多了一个任务
- [ ] 跑到一半说「停下」→ 它调 interrupt，图真的停了
- [ ] 说「把排队的都清掉」→ 它调 clear_queue，等待中的队列清空了（正在跑的不受影响）
- [ ] **故意不说停**，看它会不会自作主张去调 interrupt（应该不会）
- [ ] 一次要求改一堆参数（「步数改 30、CFG 改 7、种子随机」）→ 它逐条改完再回报
- [ ] 让它改一个**不存在的节点编号** → 它把「找不到」如实告诉你，而不是假装改好了

### 小鲸鱼 · 快捷选项

三个按钮各对应一套写好的指令。测的时候重点看**它有没有守住预设里的约束**。

- [ ] 对话框输入框上方能看到三个圆角按钮：跑一张图 / 选 LoRA / 查报错
- [ ] 点下去之后，那段指令会先出现在输入框里再发出去（不是凭空冒出一句话）
- [ ] 点「跑一张图」→ 它看画布、自己写提示词、填进去、提交排队，并告诉你写了什么
- [ ] **在一个空画布上点「跑一张图」** → 它把缺什么说清楚，而不是乱改或硬跑
- [ ] 点「选 LoRA」→ 它调 list_loras，推荐 3-5 个并说明理由
- [ ] 点「选 LoRA」后问它要不要填进去 → 它**先问**，不是直接改画布
- [ ] 点「查报错」，**在没有失败记录的时候** → 它直说没有，而不是编一个错误给你
- [ ] 故意跑一个会失败的任务，再点「查报错」→ 它能指出是哪个节点、什么错误
- [ ] 它正在回答时，三个按钮变灰点不动

### 小鲸鱼 · 余额气泡的样子

- [ ] 点挂件，弹出的是**白底深蓝描边的思考气泡**，尾巴是从椭圆本体伸出的一个锥形，下面再跟两个递减的圆点
- [ ] 三行内容：`DeepSeek 余额` / 大号金额（带 ¥）/ `今日已用 …`
- [ ] **出现时三个部件依次弹出**：下面那个小圆点先、中间圆点次之、椭圆本体最后（不是一起冒出来）
- [ ] 收起时顺序反过来
- [ ] 气泡是**安静的**，没有上下浮动（原版就没有，别加上去）

- [ ] 把上一步的图传进去、密钥填一样 → 点「解回来」
- [ ] **得到的就是原图，逐像素一致**（和原图来回切着看，找不出任何差别）
- [ ] 故意换个错密钥 → 解出来还是乱码（说明密钥是真在起作用）
- [ ] 故意改一下密钥串里的字符 → 提示「指纹对不上」，并说明解出来多半还是乱码
- [ ] 密钥串留空、只填密钥 → 也能解，但块大小要和混淆时一致

**嵌套 · 混淆**

- [ ] 切到「嵌套 + 混淆」→ 多出一个上传框「要藏进去的秘密图」
- [ ] 掩护图放 512×512，秘密图放 128×128
- [ ] 点「藏进去」→ 出结果，**看着和掩护图完全一样**
- [ ] 卡片里写清：这张图能藏多少像素、实际用了多少
- [ ] 秘密图比容量大时（掩护图 256×256、秘密图 400×400）→ 自动等比缩小，**卡片里说清缩到了多少**
- [ ] 下载出来的图和原掩护图来回切 → **肉眼分辨不出**

**嵌套 · 解混淆**

- [ ] 切到「嵌套 + 解混淆」→ 第二个上传框收起
- [ ] 把上一步那张图传进去，填同一个密钥 → 点「解回来」
- [ ] 得到的秘密图和原图**逐像素一致**
- [ ] 换个错密钥 → 提示「签名对不上：密钥不对，或者这张图里本来就没有藏东西」
- [ ] 拿一张**没藏过东西的普通图**传进去 → 同样的提示，**不吐垃圾、不崩**

**选图与预览**

- [ ] 选好一张图 → 拖拽区里的「＋」换成**缩略图**，下面从「PNG / JPEG / WebP」变成**实际尺寸**（比如 320 × 200）
- [ ] 再选一张别的 → 缩略图和尺寸**跟着换**
- [ ] 嵌套混淆时选第二张 → 那个框里也有缩略图，尺寸后面跟着「会按容量自动缩放」
- [ ] 从嵌套切回小番茄 → 第一张的缩略图**还在**（不用重选）
- [ ] 点「重来」→ 缩略图收回，变回「＋」和原始提示

**通用**

- [ ] 点「重来」→ 清空回初始状态
- [ ] 切模式 / 方向 → 该出现的出现、该收起的收起（块大小只有置乱用，秘密图只有嵌套混淆用）
- [ ] 窄屏（<760px）→ 预览和信息卡上下堆叠，不横向溢出
- [ ] 四套主题下，两排分段按钮的选中态都看得清

### 像素风转化

**基本**

- [ ] 左侧菜单点「像素风转化」→ 进到页面
- [ ] 五个参数：风格 / 像素块大小 / 颜色数 / 放大倍数 / 有序抖动
- [ ] 传一张图 → 拖拽区里变缩略图，下面是它的尺寸
- [ ] 点「转化」→ 右边出像素图

**像素画的特征（这条最要紧）**

- [ ] 把输出的图存下来，**放大看**：每个像素是规整的方块，边界是**硬的**
- [ ] 边界要是发糊，说明用了插值 —— 不该发生
- [ ] 「像素块大小」从 8 改成 32 → 颗粒明显变粗，像素数变少
- [ ] 「放大倍数」从 4 改成 1 → 输出的就是原始像素尺寸，很小一张

**卷积那一段**

- [ ] 「原味」不卷积，直接面积平均
- [ ] 「标准」多一层均值 3×3 抗锯齿，比原味柔一点
- [ ] 「柔和」高斯 5×5，最柔，适合照片
- [ ] 「硬朗」抗锯齿 + 锐化，边最硬，适合线条画和二次元
- [ ] 四种风格结果互不相同 —— **纯色图除外**：卷积不改变纯色，四种结果一样是**正常的**

**减色与抖动**

- [ ] 「不限色」+ 关掉抖动 → 颜色不变，只是变粗
- [ ] 「每通道 4 档」→ 颜色明显变少，出色块感
- [ ] 打开抖动 → 过渡处出现**规则的点状纹理**（不是随机噪声）
- [ ] 选「不限色」时，信息卡里「抖动」那行显示「—」

**纯色图（边界情况）**

- [ ] 传一张纯色图 → 输出还是那个纯色，**不许出现条纹或暗角**
- [ ] 但开了减色之后色值会变（被压到最近的台阶上）—— 这是对的，不是 bug

**信息与下载**

- [ ] 「像素图」卡里有原始尺寸、像素尺寸（多少个像素）、输出尺寸
- [ ] 「这一张是怎么算的」卡里写清风格、块大小、颜色、抖动、放大
- [ ] 点「下载像素图」→ 存下来，文件名带 -pixel
- [ ] 改任意一个参数 → 提示「参数变了，点「转化」重新算一次」

### 提示词归纳

**基本**

- [ ] 左侧菜单点「提示词归纳」→ 进到页面，中间是空状态「还没有卡片」
- [ ] 右上角「＋ 新建一张卡」→ 出现一条

**一张卡**

- [ ] 名字、分类下拉、提示词框、备注框都在
- [ ] 改动之后那条**描边变色**，右边写「有改动没保存」
- [ ] 点「保存」→ 描边恢复，状态行写「存好了。」
- [ ] 「复制提示词」→ 粘到别处，内容完整
- [ ] 「连名字一起复制」→ 第一行是名字，第二行开始是提示词
- [ ] 提示词空着点复制 → 提示「这张卡还没写提示词」，而不是没反应

**例图**

- [ ] 新建一条 → 左边是一块棋盘底的方框，写着「＋ 传一张效果图」
- [ ] 点它传一张图 → 图显示出来，鼠标移上去右下角出现「换图 / 去掉」
- [ ] **传图之后那条不该变成「有改动没保存」** —— 图是直接落盘的，不走保存按钮
- [ ] 点「换图」→ 换掉；点「去掉」→ 回到「＋ 传一张效果图」
- [ ] 传一张很大的图（比如 4000×3000）→ 存进去**不卡**（存之前会压到最长边 1024）
- [ ] 传一张带透明的 PNG → 棋盘底透出来，看得出边界
- [ ] **关掉浏览器重开 → 例图还在**
- [ ] 窄屏（<720px）→ 例图跑到上面一条，不挤旁边的文字

**分类**

- [ ] 分类条上有「全部」「未分类」和一个「＋ 新建分类」
- [ ] 点「＋ 新建分类」→ 弹出输入框，回车就能确定
- [ ] 起完名字 → 分类条上出现它，后面跟着数字（里面有几张卡）
- [ ] **新建分类之后当前这一列不该变空** —— 新分类里本来还没东西，切过去会像卡片丢了
- [ ] 用卡片上的分类下拉把卡存进分类 → 分类条上的数字跟着变
- [ ] 点分类条上某一项 → 只显示那个分类的卡
- [ ] 点「未分类」→ 只显示没归类的；点「全部」→ 都显示
- [ ] **双击分类名** → 弹出改名框，改完分类条上跟着变
- [ ] 建一个同名的分类 → 自动变成「xxx 2」，不会出现两个一模一样的

**删东西**

- [ ] 点某张卡的「删掉」→ **不是直接删**，确认框里念出卡片名和字数
- [ ] 点「取消」→ 框关掉，那张还在
- [ ] 点「确认删除」→ 才真的没了
- [ ] 分类项右侧有个 ×，点它删分类 → 确认框**说明里面的卡会变成未分类，不会被一起删掉**
- [ ] 确认删分类 → 分类没了，**里面那些卡一张都没少，只是变成未分类**

**关掉再打开**

- [ ] 建几张卡、分好类 → **关掉浏览器重新打开** → 卡和分类都还在，内容一字不差
- [ ] 隐身模式下打开 → 提示「这个浏览器不给存东西」，新建时也如实说，**不假装存上了**

### 备份（导出 / 导入）

三个有本地数据的地方各有一对按钮：OC 工坊、提示词归纳、贴纸库（在图片工坊那一栏）。

**导出**

- [ ] 三处都能看到「导出备份 / 导入备份」
- [ ] 有数据时点「导出备份」→ 下载一个 json，文件名带日期时间（比如 m8-oc-20260921-2037.json）
- [ ] 里面例图是内嵌的，所以文件可能几十 MB —— 这是对的，备份就要有备份的质量
- [ ] 没有数据时点「导出备份」→ 提示「还没有东西可以导出」，不下载空文件
- [ ] 贴纸库只导自己导入的那些，内置贴纸不占备份体积

**导入**

- [ ] 点「导入备份」→ 选文件 → 弹出确认框
- [ ] 框里写清：这是哪个功能的备份、有几条、当前页面上有几条
- [ ] 三个按钮：取消 / 合并导入 / 清空后导入
- [ ] **合并导入**：同名的跳过，其余加进来，现有的一条都不动
- [ ] **清空后导入**：先清空再灌，之后条数正好等于备份里的条数
- [ ] 完事状态行写清「新增 N 条、跳过同名 M 条」
- [ ] **提示词归纳**：分类跟着一起搬，卡片的分类归属不许串
- [ ] 选错文件（把 OC 的备份导进提示词页）→ 提示「这份备份是「OC 工坊」的，不是提示词归纳的」
- [ ] 选一个不是 M8 备份的 json → 明确说不是 M8 的备份
- [ ] 选一个更新版本导出的 → 明确说这个版本读不了

**真丢了能救回来（最要紧的一条）**

- [ ] 建几条数据 → 导出备份
- [ ] **换一个浏览器**（或者换台机器）打开工作台 → 那里是空的
- [ ] 用刚导出的文件导入 → **内容、分类归属、例图全都回来**

**持久化**

- [ ] 第一次打开某个页面 → 如果浏览器没给持久化权限，状态行会提示「磁盘紧张时可能被清掉，记得导出备份」
- [ ] 这不是错误，只是提醒；不给权限照样能用

## 四、发现问题怎么回报

**删除要二次确认**

- [ ] 点某条的「删掉」→ **不是直接删**，弹出确认框
- [ ] 框里**念出要删的是哪个**（名字），并写清「删了找不回来」
- [ ] 点「取消」→ 框关掉，那条**还在**
- [ ] 再点「删掉」→ 点「确认删除」→ 那条才真的没了
- [ ] 按 **Esc** → 关掉框，不删
- [ ] 点框外的暗色区域 → 同样关掉，不删
- [ ] 点右上角 **×** → 同样关掉
- [ ] 框开着的时候**背景不能跟着滚**
**按这个模板贴回来就行**。信息齐了，多数问题看一眼就能定位到货架和文件；
缺了控制台日志，就只能靠猜，来回好几轮。

```

【预期】下拉里出现模型列表
【错误码】M8-LLM-003（通知里带的那个码，有就抄下来）
【复现步骤】
  1. 右键加 M8 · 大模型推理
  2. provider 选 deepseek，填了一个假 Key
  3. 点「刷新模型」

【控制台 [M8] 日志】
（ComfyUI 控制台里搜 [M8]，把相关几行贴过来）

【浏览器控制台】

```
