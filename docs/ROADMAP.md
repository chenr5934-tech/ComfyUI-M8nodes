# M8 节点包 · 货架规划蓝图

> 这是这个插件的"图书馆编目表"。新东西先在这里找到自己的货架，再动手写代码。
> 没找到货架 = 先加货架，别把节点塞进不相干的地方。

---

## 一、为什么要分货架

节点包长到几十个之后，最痛的不是写不出来，是**找不到**：

- 报了个错，得从头翻一遍才知道是哪个文件的事
- 想改 LoRA 加载，结果在图片处理的文件夹里找
- 同一个功能写了两遍，因为在两个货架上各放了一个

所以这里按**它在工作流里干的活**分类，不按"先后写出来的顺序"分。
每个货架有明确的**职责**和**边界**（边界比职责更重要，划清边界才不会长歪）。

## 二、货架总表

| 货架 | 目录 | 错误码段 | 职责 | 明确不做 |
| --- | --- | --- | --- | --- |
| **地基** | `m8/core/` | `M8-CORE-###` | 注册中心、错误体系、日志、配置读写 | 不含任何节点 |
| **接口** | `m8/server/` | `M8-SRV-###` | 后端 HTTP：模型列表、skill 文件、密钥存取 | 不含节点业务逻辑 |
| **大模型** | `m8/nodes/llm/` | `M8-LLM-###` | 远程：调外部模型 API（推理、看图、skill 装配）。本地：`llm_local/` 跑 GGUF，识图走 mmproj | 不做音频识别、不训练、不管显存分配策略 |
| **加载器** | `m8/nodes/loaders/` | `M8-LOAD-###` | 底模 / CLIP / LoRA / VAE / ControlNet 的加载与切换 | 不采样、不改像素 |
| **采样** | `m8/nodes/samplers/` | `M8-SAMP-###` | 采样器、调度器、步数/CFG 控制、噪声注入 | 不加载模型 |
| **判断** | `m8/nodes/logic/` | `M8-LOGIC-###` | 条件分支、比较、布尔开关、值路由 | 不做数据转换 |
| **图像** | `m8/nodes/image/` | `M8-IMG-###` | 图像选择（第 N 张 / 按规则挑）、尺寸、拼接、比较 | 不做加载 |
| **文本** | `m8/nodes/text/` | `M8-TXT-###` | 文本拼接 / 替换 / 正则 / 分行 / 编码 | 不做提示词模型编码 |
| **工具** | `m8/utils/` | `M8-UTIL-###` | 跨货架复用的纯函数 | 不做 IO、不碰节点 |
| **界面** | `m8/ui/` | `M8-UI-###` | 改界面本身：侧边栏、悬浮挂件、对话框 | **不产出节点** |
| **相机** | `m8/nodes/cam/` | `M8-CAM-###` | 把取景意图翻译成提示词：机位方位 / 高度 / 距离 / 倾斜、镜头与构图 | 不采样、不加载、不碰像素 |
| **提示词** | `m8/nodes/prompt/` | `M8-PROMPT-###` | 组装提示词结构：多角色分块、区域权重、格式模板 | 不做模型编码、不采样、不碰像素 |
| **网页** | `M8web/` | `M8-WEB-###` | 插件自带的独立网页工作台（首页 + 各功能页），从顶栏按钮进入 | **不产出节点**、不碰工作流数据 |

**放不进任何货架** → 说明它是新领域。**开一个新货架，别硬塞。**

硬塞的代价当天看不出来：它会安静地待在不该待的地方，直到半年后有人要改它，
把六个货架翻了一遍才找到。判断依据只有一个：**它在工作流里干的活**，
不是「它跟谁长得像」「它跟谁一起用」。

新货架要同时登记三处：

1. 本文件的货架总表（分配一段新的错误码）
2. `m8/core/errors.py` 的货架白名单（`M8-CORE-###` 那段注释下面的 `ERRORS` 表）
3. `docs/ERROR-PLAYBOOK.md`（新码段下要有表格，哪怕是空的）

货架名**不能叫「杂项」「其他」「工具」**这类。那种名字等于承认分类失败，
很快会被当成垃圾桶，堆满互不相干的东西。宁可多开一个货架。

## 三、货架细则

### 大模型 `m8/nodes/llm/`

这是最先落地、也最可能长大的货架。它管的是"**把工作流里的数据喂给外部大模型，再把结果拿回来**"。

边界划法：
- **算力的家在别人那儿**。本货架只负责组装请求、发出去、解析回来。不碰显存、不碰 torch 模型。
- **供应商差异必须收在一处**。DeepSeek / OpenAI / 本地 Ollama / 任何兼容 OpenAI 协议的端点，差异全在 `m8/server/providers.py` 里描述（默认地址、模型列表端点、思考字段名、思考参数名）。节点代码里**不许出现 if 供应商 == ...**。
- **密钥不进工作流文件**。API Key 存在服务端 `m8/data/credentials.json`，节点上只显示后四位。工作流发给别人的时候不能带着 Key 走。

规划中的节点：

| 节点类名 | 显示名 | 状态 | 说明 |
| --- | --- | --- | --- |
| `M8SkillLoader` | M8 · Skill 装载 | **v0.1 首批** | 上传/选取 skill 文件，输出给推理节点当"知识包" |
| `M8LLMInference` | M8 · 大模型推理 | **v0.1 首批** | 双提示词框（系统 + 对话）+ 模型下拉 + 思考强度 + 图片/音频输入 |
| `M8LLMLocal` | M8 · 本地大模型推理 | **v0.3** | 在**本机**跑 GGUF，不联网、不花 API 钱；配 mmproj 能识图。依赖 `llama-cpp-python`（可选，缺了只有它报错） |
| `M8LLMChat` | M8 · 多轮对话 | 规划中 | 带历史的多轮，用 `M8ChatHistory` 类型传递 |
| `M8LLMStructured` | M8 · 结构化输出 | 规划中 | 强制 JSON schema 输出，给下游节点当参数用 |

### 网页 `M8web/`

这个货架**不产出节点**：它是一个独立网页，放那些「不适合塞进节点」的工具 —— 批量裁图、
贴纸排版、混淆图、像素风转化、提示词归纳这类，都是要来回看、来回调的活，
塞进节点面板只会两头难受。

边界划法：
- **数据必须离开插件目录**。工作台里的东西（OC、提示词、贴纸库）是用户一条条攒出来的，
  而插件更新会把 `custom_nodes` 下的东西整个换掉。所以数据落在
  `<ComfyUI>/models/M8data/webapp/*.json` —— 升级、重装都带不走它，备份复制文件夹就行。
- **也和浏览器无关**。早先存在 IndexedDB 里，换浏览器、换机器、清缓存就没了，
  而且写不进去时浏览器不给理由。现在只有服务端文件。
- **两个门进同一份数据**：ComfyUI 顶栏的 `M8` 按钮，和 `M8web/start-workbench.bat`。
  后者拉起的独立服务（`m8-serve.py`）只用标准库，所以 **CUI 关着照样能用**。
  它不知道自己的数据目录在哪，靠 `M8web/.m8data` 这个路标 —— 那是 ComfyUI
  加载插件时用 `folder_paths` 算出来写下的。

### 加载器 `m8/nodes/loaders/`

规划：`M8CheckpointLoader`（底模 + 可选 CLIP/VAE）、`M8LoraLoader`（带开关和权重的 LoRA 栈）、`M8ClipLoader`、`M8VaeLoader`。
核心诉求是"**少连线、可切换**"——一个节点解决常见组合，而不是四个节点串起来。

### 采样 `m8/nodes/samplers/`

规划：`M8KSampler`（把 sampler/scheduler/steps/cfg/denoise 收成一套可保存的配置）、`M8SamplerConfig`、`M8SeedControl`。

### 判断 `m8/nodes/logic/`

规划：`M8IfElse`（任意类型直通式分支）、`M8Compare`、`M8Switch`、`M8Gate`（执行开关）。

### 图像 `m8/nodes/image/` 

规划：`M8ImagePicker`（批次里按序号/规则取第 N 张）、`M8ImageBatchSwitch`、`M8ImageSizeInfo`、`M8ImageCompare`。
