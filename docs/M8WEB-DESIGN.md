这套界面不是自己想的 —— **整份取自参考站 azusa.nyacraft.cn**。抓下来的原件
（就是下表那几个文件）留在开发机上，没随仓库分发：表里的行数是照着它们数的，
自己重新抓一份就能逐行对上。

## 结构

```
M8web/
  index.html            首页：大标题 + 3 列卡片
  pages/<功能>.html     每个功能一页，现在都是空状态
  assets/css/base.css   四套主题 + 噪点 + 动效层
  assets/css/shell.css  外壳：侧栏 / 首页卡片 / 主题条 / 空状态
  assets/css/studio.css 图片工坊：工作台、分割虚线、黑条、屏蔽按钮、预览
  assets/js/app.js      功能清单 + 侧栏 + 主题（外壳的唯一来源）
  assets/js/studio.js   工坊公共部分：上传 / 拖放 / 粘贴 / 图片状态 / 标签切换
  assets/js/cut.js      分段裁剪
  assets/js/mask.js     分段遮挡
  assets/js/grid.js     宫格拼图（2×2 到 5×5）
  assets/js/sticker.js  贴纸遮挡 + 内置抠图（去同色背景）
  assets/js/sticker-store.js  贴纸库的 IndexedDB 存储层
```

早先照抄参考站的那版工坊（`_parked/`）在 0.5.3 删掉了：从未接进菜单，
也没有任何运行时引用，留着只是让审核看到一堆不会执行的中文界面代码。
需要它的话在 git 历史里能找到。

**外壳只有一个事实来源**：`app.js` 里的 `FEATURES` 数组。首页卡片和左侧菜单
都从它生成，加功能只改这一处。

几个必须知道的约束：

- **主题挂在 `<html>` 上**（`document.documentElement.dataset.theme`）。head 里那段
  防闪脚本设的也是它，两处必须一致，否则点了主题会被盖回去。
- **侧栏收起状态是 `<html>` 上的一个类**（`is-side-collapsed`），CSS 靠它切
  `--side-w`。不要用 `display:none` 那套，参考站用的是宽度过渡。
- **`#fx` 动效层不吃点击**（`pointer-events:none`），`z-index` 压在内容下面。
- **卡片必须有三个直接子元素**：`.card-kicker` / `<strong>` / `<small>`。
  父级是 `align-content:space-between` 的网格，少一层排版就垮。

## 图片工坊 · 分段裁剪

**布局**：图片在左侧占大头，工具在右侧一列。横切时屏蔽按钮是图片右侧的竖排，
竖切时变成图片上侧的横排 —— 就是「每段右侧 / 上侧」。

**两处刻意不靠像素的设计**（缩放窗口、切方向都不会错位）：

- 段的位置一律存**百分比**（`cuts[i]`）。只有拖拽那一瞬间才拿容器真实像素去夹边界，
  因为同样的百分比在横切和竖切下对应的视觉距离差很远。
- 屏蔽按钮的**对齐靠 flex 权重**：每个按钮的 `flex-grow` 就是它那一段的占比，
  段多高按钮就多高，天生严丝合缝，一个像素都不用算。

**几条不要走回去的路**：

- 段数 n 对应 **n-1 条线**；线和段都从 `cuts` / `muted` 两组数推出来。
- 改段数**一律重新等分**。曾经试过「保留用户拖过的位置」，结果从少段往上加时
  新线会插到旧线前面，`cuts` 变成乱序，段宽直接算成 0。等分永远单调。
- 拖拽监听挂 **document**。挂圆点上或画布上，指针一移出那块区域就断，
  表现为「拖到边缘卡住，得松开重按」。
- **拖动过程中不能整层重画**：重画会把手上抓着的那个圆点节点换掉，指针就丢了，
  表现为「拖一下断一下」。只更新位置和蒙版层，松手时才整层重画。

## 图片工坊是怎么搭起来的

工坊下面的功能会一直加，所以分了两层：

- **`studio.js` 管公共部分**：上传、拖放、粘贴、当前是哪张图、标签切换。
  图片只有一份，切功能不用重新传。
- **每个功能一个自己的 js**（`cut.js` / `mask.js`），只订阅
  `M8Studio.onImage(fn)` 拿图，然后管自己那套参数和渲染 —— 互相不知道对方存在。

功能之间有一条**故意不一致**的地方，别当成 bug：
分段裁剪的 n 段是 **n-1 条线**，条之间**不能越界**；分段遮挡的 n 条就是
**n 条**遮罩，条之间**允许重叠**（想连成一片就拖到一起）。

## 往图片工坊里加一个功能

1. `pages/image-editor.html` 顶部 `.shop-tabs` 里那个按钮去掉 `disabled`
2. 加一组 `.shop-pane[data-pane="新 id"]`：图片区 + 右列工具栈 + 预览区
3. 新建 `assets/js/<新 id>.js`，在 `init()` 里 `M8Studio.onImage(...)` 接图，
   然后渲染自己那套东西
4. 页面底部按顺序引入这个 js，并在最后那段内联脚本里调它的 `init()`

工具栈（`.studio-side`）是 flex 列，卡片随便加几张都不会错位。唯一要注意：
**只能让一张卡标 `.stretch`** —— 它负责吃掉剩余高度，否则右列底下会留一大片空。

另外，凡是**按容器像素算字号或尺寸**的地方（比如遮挡条上的文字），
都得先给容器定死 `aspect-ratio`：`<img>` 解码是异步的，那一刻容器高度还是 0，
算出来全是兜底值。

## 贴纸遮挡与抠图

抠图就是**把和取样色相近的像素抹成透明**：在对话框里点图上要去掉的颜色，
容差滑块决定「多接近才算同色」。几条踩过的点：

- 每次重算都从**未处理的原始像素**（`draft.base`）出发。在已经抠过的图上再抠会越抠
  越花 —— 过渡带会一层层叠上去。
- 容差是**颜色距离**（RGB 空间，最远 441.7）按百分比映射，不是逐分量比大小。
- 边缘留一档过渡（`soft`）。不留的话抠出来是一圈硬锯齿，贴到图上很脏。
- **容差给 0 时 `soft` 必须是 0**。兜到 1 的话判定式变成 `dist <= -1`，等于什么都不做 ——
  而用户把容差归零恰恰是想要「只抹一模一样的那一个」。
- 取色要从原始像素取，**不能从画布取**：画布上那块可能已经被抠成透明了，取到的是黑。

## 宫格拼图：裁满，而不是拉伸

这个功能是**导入多张图拼成一张**（1 ~ 25 张），和工坊里其它功能不一样 ——
它们共用 `studio.js` 那张单图，而这里要一次拿很多张，所以自己管上传。

每格填图用 **cover**：
- 拉变形（把图直接铺满格子）是最难看的错法，坚决不用；
- 留边（contain）会让网格看起来参差不齐；
- DOM 预览用 `object-fit: cover`，canvas 用 `coverRect()` 算源矩形 ——
  **两处必须是同一套规则**，否则预览和导出对不上。

张数和格子：
- 导入的张数超出当前网格时**自动跳到装得下的最小网格**（9 张 → 3×3）。
  不跳的话用户会以为只认了 4 张。
- 上限 25 张（5×5）。判上限要用独立的 `pending` 计数，**不能用
  `images.length + 本批已接受数`** —— 图片加载可能同步完成（测试桩就是），
  那时 `images.length` 已经含了本批前面的那些，再加一遍就是重复计数（实测 30 张只进了 13 张）。
- 装不下的那几张在缩略图上**标灰**，不会被拼进去。

重排用的是**插入**语义（`moveTo(from, to)` 里先把那张摘出来、再插到目标位），
不是交换：「把第 5 张拖到最前面」时其它图应该顺延一位。另外拖拽有个 6px 的启动阈值 ——
不设的话，想去点缩略图上的删除钮、手一抖就先改了顺序。

## 贴纸库存在哪

用 **IndexedDB**（`sticker-store.js`），不是 localStorage —— 贴纸是一张张 PNG，
localStorage 只有 5MB 左右，存三四张就写不进去，而且它只收字符串。

- 内置那张是**文件**（`assets/stickers/default-sticker.png`），不是 dataURL：
  不占存储空间，也不可能被误删。
- 用户导入的存成 dataURL，带时间戳，读回来时新的排前面。
- 存储层整个不在时（隐身模式、老浏览器、Node 测试环境）**安静降级**：贴纸库只剩内置那张，
  其余功能照常，提示里会说清楚「这个浏览器不给存东西」。
  所有调用都要走 `storeReady()` 守卫 —— 直接摸 `M8StickerStore` 会 ReferenceError。

> 验证持久化**必须走 http://**：用 file:// 打开时 IndexedDB 归到 opaque origin，存不住。
> 这个工坊本来就是通过 ComfyUI 的 `/m8/web/` 路由访问的，线上没这个问题。

## 文字与画笔：别去量容器像素

字号和线宽存的都是「占图片宽度的百分比」，显示和导出都按这个换算。关键在于
**显示时不要去读 `getBoundingClientRect()`**：

- 文字字号用 **`cqw`**（容器查询单位，1cqw = 容器宽的 1%），容器上声明
  `container-type: inline-size`。它本身就是「宽度百分比」，浏览器自己会算；
  canvas 那边是 `W × size / 100` —— 两套天然是同一个数。
- 画笔 canvas 用**固定内部基准**（1200 宽 × 图片比例），CSS 拉伸铺满。
  笔画坐标本来就是百分比，基准取多少都不影响成品；导出又是按原图尺寸重绘的，
  清晰度也不受这里影响。

为什么不量？因为量不准的场合太多：面板刚切过来浏览器还没重排、面板还藏在别的标签下
（尺寸是 0）、无头环境里根本没有布局。这些情况量到 0 会让字号全变成兜底值、
canvas 变成 1×1 —— 而且**页面一声不吭**，最难查。这一版就是在这些问题上绕了两圈才改对的。

拖拽和画笔的坐标转换（`pointAt`）仍然要读 rect，但那是**用户交互时**发生的，
那时面板一定可见、一定布局过了。

## 往页面里插整块面板时，先确认锚点

往 `image-editor.html` 插新功能的 `.shop-pane` 时，**锚点必须落在上一个 pane 的闭合
`</div>` 之后**，不能落在它内部的某个 `</div>` 上。踩过一次：锚点选在 grid pane 的
`.studio-grid` 收尾处，新 pane 被插进了 grid pane **内部**，后果是：

- grid 一隐藏，paint 面板跟着一起藏；
- 里面所有元素尺寸都是 0，`aspect-ratio` 把高度也带成 0，整块画布看不见；
- **而点击、画笔、文字这些逻辑其实全都正常**，页面上也**不报任何错**。

最难查的就是这种：症状全在布局上，根因在 HTML。当时我在 CSS 上绕了三轮
（先怀疑字号换算、又怀疑 `container-type`），最后靠**截图里那块红色底图不见了**
才回头查结构。

所以 `tests/frontend_webapp.js` 里加了两条机械检查：
**div 标签配平** + **两个 pane 之间不许再冒出 pane 开始标签**。
插完面板先跑一遍，几秒钟就能撞出来，比对着空白面板猜快得多。

## OC 工坊

一个原创角色一条：左边例图、右边特征词。几个决定：

- **例图压到最长边 1024px 再存**。原图动辄几 MB，存几十个就把 IndexedDB 的配额吃光了，
  而展示用的缩略图本来也不需要原尺寸。
- **编辑时不能整列重建**。`render()` 是清空再重建，如果每次打字都调它，
  正在输入的那个 textarea 会被换掉 —— 光标一丢字就断了。所以只有**增删**才 `render()`，
  改动只走 `markDirty()` 更新那一条的描边和状态文字。
- **例图上传后立刻落盘**：它不像文字那样能随手重打，丢了就没了。
  而且只刷新那一条的图片区（`refreshRowMedia`），不整列重建。
- 存储层整个不在时（隐身模式、老浏览器）**明确告诉用户**「这次加的内容关掉就没了」，
  不能假装存上了。
- **删除走二次确认**，而且框里要把要删的那个名字念出来。一条里可能写着几十个字的
  特征词和一张例图，误点一下找不回来。焦点默认落在「取消」上 —— 这个框弹出来多半
  是因为手滑，默认该是「算了」。名字拼进 HTML 前要转义，否则名字里带个尖括号
  就能把结构撕坏。

模态框（`.modal` 那一套）放在 **shell.css** 里而不是 studio.css —— OC 工坊那个页面
不引 studio.css，但也要用同一个确认框。

## 公共样式不要放进功能样式表

`.is-hidden` 原来写在 `studio.css` 里，只有图片工坊那个页面引了它。
OC 工坊不引 studio.css —— 结果它对 OC 页面**完全无效**，那个删除确认框
**从一进页面就一直显示着**（浏览器眼里它一直是 `display:block`），
用户看到的就是「还没加 OC 就问我删不删」。

判据很简单：**只要有两个页面可能用到，就放 shell.css**。
按钮（`.gen-btn` / `.ghost-btn`）、状态行（`.status`）、隐藏工具类（`.is-hidden`）、
模态框那一套（`.modal*`）都属于这一类，现在都在 shell.css。
测试里钉了一条：这几个类**不许再出现在 studio.css**。

同一轮还修了另一个：`init()` 原来只在 IndexedDB 回来之后才 `render()`，
它慢或者卡住时页面会一直空白。现在**先同步渲染一次**（空状态立刻出来），
再异步把数据补上。

## 图片元数据：纯字节解析

三块解析全是纯函数（吃 `Uint8Array` 吐对象），所以测试里是**自己造字节流**来验的，
不用准备真图片：

- `parsePng()` —— PNG 是一串 `[长度][类型][数据][CRC]` 的 chunk。
  ComfyUI 把工作流和生成参数塞在 `tEXt` 里，关键字是 `workflow` 和 `prompt`。
- `parseJpeg()` / `parseTiff()` —— EXIF 在 APP1 段里，跳过 `Exif\0\0` 之后是一份 TIFF。
- `extractComfy()` —— 从节点字典里挑出模型、LoRA、采样器、步数、CFG、种子。

**两个格式的字节序是反的**：PNG 的块长度是**大端**，TIFF 是**小端**。
我在测试的构造函数里一开始共用了同一个大端写入函数，结果四条 EXIF 断言全挂，
看着像解析器坏了 —— 其实是喂进去的数据本身是反的。这两种格式同时出现在一个项目里
特别容易踩，所以测试里干脆分成 `w32`（大端）和 `w32le`（小端）两个函数。

**ComfyUI 塞中文提示词时塞的是 UTF-8 字节**，而 `tEXt` 名义上是 latin1。
所以解码走 `smartText()`：全 ASCII 就用 latin1，一旦出现高位字节改用 UTF-8 ——
不然中文提示词会变成一串问号方块。

解析器对坏数据一律**安静地少给点信息**：截断的文件能读多少读多少、
长度字段坏掉的不进死循环、根本不是图片的返回 null 而不是抛异常。
测试里专门验了这几种：坏长度、截断、野数据、null。

## LoRA 解析：读头部，不读模型

safetensors 只有三层：

```
[8 字节：header 的字节数，小端 u64]
[那一段：JSON header，含 __metadata__ 和张量清单]
[剩下的：张量数据]
```

所以解析只做两次切片：`file.slice(0, 8)` 拿长度，`file.slice(8, 8 + len)` 拿 header。
**张量那一段一个字节都不碰**，几百 MB 的模型也是一瞬间，而且不用把它读进内存。

实测（真浏览器里用 `File` 跑，统计 `slice` 的字节数）：

| 文件 | 大小 | 实际读了 | 占比 |
| --- | --- | --- | --- |
| 合成样本（2 个张量） | 2.1 MB | 8 019 B | 0.4% |
| KAWAII STYLE_XL（3194 个张量） | 7.1 MB | 715 368 B | 9.6% |
| salt-lokr（1524 个张量） | 4.2 MB | 193 280 B | 4.4% |

真文件的 header 有几百 KB —— 因为张量名很长、数量上千。但 header 是**跟张量数走、
不跟模型体积走**的，所以模型越大这个占比越小。

测试 `tests/frontend_lora.js` 里把这条钉住了：喂一个 20 MB 的假模型进去，
断言 `slice` 只被调用两次、总读取量等于 `8 + header 长度`、且远小于文件体积。

「读完删除上传的文件」在这套架构里是这么落的：文件**从头到尾没离开过用户磁盘**
（浏览器只是拿了个句柄），没有任何字节被写盘或发到网络。读完把 input 的 value
和内存引用清掉就完事了。页面上把这点写成了显眼的说明 —— 用户会担心几个 G 的模型被传走。

## 四种真实噪音，四种处理

真文件里有一堆东西会毁掉一屏显示，都是扫出来才知道的：

**同义键重复**。`ss_steps` 和 `ss_max_train_steps` 各出现 460 次且值相同，
照实显示就是同一张卡里「训练步数」出现两遍。做了张 `SYNONYMS` 表：
主键没值时回落到旧名，被回落过的旧名也不再单独列到「其他参数」。
**方向别写反** —— 该跳的是别名不是主键，反着写主键反而会从兜底列表里冒出来（踩过）。

**Python 的 None**。kohya 是 Python 写的，没设的项写成**字符串 "None"**。
`ss_network_dropout` 449 次、`ss_min_snr_gamma` 446 次、`ss_noise_offset` 433 次
带的都是这个值。照实显示就是满屏 "None"，现在当没值处理。
但 "True" / "False" 要保留 —— 那是真信息（某项没开）。

**空的标签组**。`ss_tag_frequency` 里 774 个文件有 41 个是 `{"resized": {}}` 这种空壳。
不过滤掉就会画出一张标题写着组名、里面什么都没有的标签卡。

**内嵌缩略图**。`modelspec.thumbnail` 是一段几百 KB 的 base64 JPEG，
跟训练参数毫无关系，列出来会把「其他参数」变成一屏乱码。列进了 `SKIP_KEYS`，
只在卡片底部报一句「省略了 N 项」——原始内容在「复制」拿到的 JSON 里仍然完整。

## 一张卡不够：按用途分组

真文件的 `ss_*` 键数到过 **115 个**。一坨列下来没人看得完，所以分了四组，
每组渲染成一张卡，**空组不出现**：

- **训练参数**（kohya）—— 输出名、底模、网络、dim/alpha、学习率组、优化器、调度器、步数/轮数、批大小、分辨率、精度、种子
- **训练过程**（来源）—— 第一行是**现算的训练耗时**（起止时间相减），下面有梯度裁剪、会话 ID、训练器 commit、底模 hash、VAE
- **数据集与标注**（captions）—— 数据集目录、分桶、保留 token、打乱标注、标注丢弃率、增强开关
- **噪声与采样**（进阶）—— 损失函数、加权方式、时间步采样、噪声偏移、Min-SNR

`ss_network_args` 那串 JSON（`{"algo":"lora","factor":8,...}`）会拆成
「网络参数 · algo」这样一条条，比塞一整坨 JSON 好读。

## 小番茄混淆：为什么一个参数都不能改

这是梦羽小番茄那版的做法：沿 Gilbert 曲线（空间填充曲线）把整条像素序列循环移位，
移位量是 `Math.round((√5 − 1) / 2 × 像素数)` —— 黄金分割比乘像素数，没有密钥。

移植的时候只改了一处：原版 `gilbert2d` 每生成一个点就 `push([x, y])`，
1024×1024 就是现场造一百万个两元素数组；这里改成写进一个交错的 `Int32Array`。
**两个递归函数一字未动** —— 这是刻意的，因为要保证逐像素等价。

**为什么坚持不加密钥**：加了密钥就和原版不互通了。现在的状态是两边能互解 ——
原版混淆的图这里能解，这里混淆的图原版能解。测试里把原版那份实现逐字抄了一份当参照物，
验三件事：混淆结果逐字节相同、解除结果逐字节相同、以及双向互解都能还原。
这比「自己写的自己证明能还原」有说服力得多。

**一个数学上的边界**：单像素图 `n = 1` 时 `round(0.618 × 1) % 1 = 0`，
置换退化成自映射，图不会变。这不是 bug，第一版测试没把这条例外算进去，
断言「混淆了但图没变」就红了 —— 改的是测试不是代码。

**尺寸必须原样保留**：移位量是按像素数算的，裁剪或缩放之后就对不上了。
页面的说明里写了，测试里也钉了「尺寸不变」。

**它长什么样**：因为像素是按空间邻近顺序走的曲线，循环移位之后会产生沿曲线的条纹感，
和置乱那种块状乱码长相完全不同。两种都在，默认是小番茄 —— 那是这个工具的原始形态。

## 混淆图：两种可逆，一条硬约束

两种模式都只用了「置换」和「异或」这两类可逆运算，所以能还原是结构上保证的，
不是靠调参调出来的：

- **置乱**：按块切网格，块间做 Fisher-Yates 置换，块内像素再用另一个种子洗一遍。
  密钥经 FNV-1a 派生种子，同一个密钥 → 同一套置换表 → 逆着走一遍就回来。
- **嵌套**：掩护图每个像素让出 R/G/B 各一个最低位，秘密图的字节流异或密钥流之后写进去。

**块尺寸不能整除的时候怎么办**。第一想法是把图 padding 到整数倍、做完再裁回来，
但那样补的零像素会被搅进结果里，就不是无损了。改成按块的**实际尺寸分组**，
只在同尺寸的块之间置换 —— 边缘那些不满一格的块自己在小圈子里换。
代价是边缘一圈的乱度略低，换来的是严格的逐字节无损。

**块大小有个反直觉点**：块设得比图还大时，块间置换会退化成恒等（只有一个块），
这时候全看块内打散。两种参数都能出乱码，只是长相不同。测试里专门留了一条钉住这个行为
（第一版那条断言还写反了，把「应该跟原图一样」写成「如果一样就报错」，红了一阵才发现是测试的锅）。

**指纹**。混淆时把结果的 FNV-1a 写进密钥串；解混淆先算一遍输入图的指纹去比对 ——
不符就当场说「这串不是配这张图的」，省得用户对着乱码猜。这一步零额外成本，
因为输入本来就是那张混淆图。

**嵌套的容量**：掩护图 3 位/像素，减去 12 字节头部，每个秘密像素要 24 位 ——
也就是秘密图面积不能超过掩护图的八分之一。超了就按面积等比缩，缩了多少写在结果卡里。

**一条硬约束：必须存 PNG**。JPEG 有损，而它压掉的恰好是低位 —— 低位正是嵌套藏东西的地方。
所以页面上那句话是加粗的，样式也做得显眼。

实测（真浏览器里跑完整链路，不是只测纯函数）：

- 置乱 256×256：混淆后 115 326 / 262 144 字节变了；**还原后差异 0**
- 同一个混淆图换个错密钥还原：仍有 113 616 字节不同 —— 密钥确实在起作用
- 嵌套 256×256 藏 64×64：掩护图**高七位改动 0**、低位改动 49 164；**取回的秘密图差异 0 通道**
- 嵌套错密钥：签名对不上，明确报错而不是吐一堆垃圾

**已知的技术债**：`infoCard` / `kv` / `copyButton` 这三块在 lora.js 和 obfuscate.js 里各写了一份。
样式那一轮已经抽过（搬进 shell.css），js 还没抽 —— 等第三个页面也要用的时候再动手。

## 像素风：为什么不用 canvas 缩放

整条链路是五个普通步骤，没有黑箱：

1. **抗锯齿卷积** —— 对称一维核自己卷积自己（可分离），先横后竖。
   边界用 clamp（复制边缘像素）；补零的话图边会暗一圈。
2. **面积平均降维** —— 每 block×block 个源像素平均成一个。块不满时按**实际像素数**算，
   不然边缘那一条会发暗。这一步本身就是「均值卷积 + 步长采样」，也就是池化。
3. **锐化卷积** —— unsharp：原图 + amount × (原图 − 模糊)。降采样把边磨圆了，这一下咬回来。
4. **减色 + 有序抖动** —— Bayer 4×4。选它不选 Floyd-Steinberg，是因为像素风的抖动要的就是
   那种规律点阵感，随机噪声反而糊。
5. **最近邻放大** —— **这一步决定了像不像像素画**。换成双线性，出来的只是一张低分辨率糊图。

**为什么不用 canvas 的 drawImage 缩放**：它的插值方式各浏览器不一样，默认还带平滑，
出来的边是糊的。自己卷积 + 最近邻，结果才可控、可测。

**测试里两条最值钱的不变量**：

- **纯色图经过任何一步都该还是那个纯色**。这一条一口气能抓出边界处理、取整、补零的错 ——
  降采样如果按块面积除而不是按实际像素数除，边缘那一条就会发暗，正好被它抓住。
- **最近邻放大之后，每个放大块内部的颜色必须完全一致**。这就是像素画的定义。

浏览器实测：120×90 的纯色图（210,30,90），block 8、zoom 4 → 输出 60×48。
不限色且不抖动时输出**只有 1 种颜色、0 个像素偏离源色**；开每通道 8 档后输出 4 种台阶值，
全部落在量化格上、0 个脱格。有内容的图：不限色 300 种 → 每通道 4 档 59 种 → 加抖动 52 种。

**这一版有三处红是测试自己写错，不是代码错**，都留了注释免得下次再判错：锐化那条拿了已经
模糊过的图去锐化（没多少可拉的）；块左上角先按像素图宽度数、改完又只把块号当坐标，两次都错位；
还有「等输出变化」在纯色图上永远等不到 —— 因为四种风格对纯色图的输出**本来就一模一样**，
这反倒**证明了不变性成立**。

## 提示词归纳：分类为什么单独存

OC 工坊是一条记录一个角色（带例图），这边是纯文本，多了「分类」这一层。

**分类单独一个 store，不塞在卡片记录里**。如果把分类名直接存在卡片上，那么「新建了但还没
放东西的空分类」就活不下来 —— 它没有任何卡片可以依附。分成 `cards` / `groups`
两个 store 之后，空分类也能留住。

**未分类用 0，不是 null**。IndexedDB 的 autoIncrement 从 1 开始，所以 0 不会跟任何真分类撞上，
可以直接当哨兵。配套有个坑：筛选要是写成「假值就不过滤」，筛「未分类」会退化成「全部」——
测试里专门钉了这条（`filterCards(cards, 0)` 的张数必须小于全部）。另外返回的得是新数组，
不然调用方一 push 就把内部状态改了。

**删分类不删卡片**。这是顺序问题：先把里面的卡逐个改成未分类、存回去，再删分类。
反过来的话中途失败会留下一堆指着空分类的卡。确认框里也把这件事写清楚。

**新建分类不切筛选**。第一版建完就切过去，结果当前这一列突然变空 —— 新分类里当然还没东西，
但看着像卡片丢了。实测踩到，改成不动筛选。

**改名用自己的弹窗，不用 window.prompt**。项目里别处没有用它的先例，而且无头浏览器里它直接
返回 null（测试和自动化都会挂），样式也不受控。

**还是那条铁规矩**：编辑时不能整列重建 —— 重建会把正在输入的 textarea 换掉，光标一丢字就断了。
所以只有增删和切分类才 render()，改动只更新那一条的脏标记。

实测（真浏览器，同一份用户数据连开两次）：

- 第一次：建卡、填内容、保存、建分类、归类、再建一张不归类
- 筛选三条全对：构图 1 张 / 未分类 1 张 / 全部 2 张
- 第二次（同一个 profile 重开）：**2 张卡和分类都还在**，名字、分类、提示词一字不差
- 复制：剪贴板拿到完整提示词；「连名字一起复制」拿到两行，第一行是名字
- 删分类：提示写「里面有 1 张卡…不会被一起删掉」；确认后**卡片数 2 → 2，一张没少**，
  原属那张变成未分类

分类重名会自动加后缀（构图 / 构图 2 / 构图 3），免得下拉框里出现两行一模一样的。

**例图是直接落盘的，不走保存按钮**。这一点和文字不一样：文字随手能重打，图丢了就没了，
所以传上来立刻写库、顺手清掉脏标记。反过来如果只标脏，「传了图但忘了点保存」就直接丢图 ——
而那恰好是最容易发生的事。

**存之前压到最长边 1024**。原图动辄几 MB，而卡片左边那块也就两百来像素，原尺寸既没必要
又会把 IndexedDB 的配额吃光。压缩走 canvas；万一压失败就退回原图（宁可大一点，
也别因为一张格式古怪的图把功能弄崩）。

**换图只重建图片那一块**，不整列 render —— 跟编辑文字那条规矩同一个道理，
重建会把隔壁正在输入的内容打断。

实测（真浏览器，同一份用户数据连开两次）：

- 传图后显示正常，src 是 10 370 字节的 dataURL，**脏标记仍是 false**（说明走了直接落盘那条路）
- 「去掉」之后回到「＋ 传一张效果图」，「换图」按钮组消失
- 重开页面：例图还在，**页面上的 src 和从库里读出来的完全一致**（都是 10 370 字节），
  说明是真从 IndexedDB 恢复的，不是浏览器缓存
- 存了名字之后重新渲染，例图的 alt 也跟着变成「仰拍构图 的例图」

## 备份：为什么必须有导出

工作台的数据全在浏览器的 IndexedDB 里，而 IndexedDB 挂在**源**（scheme + host + port）上，
不是挂在插件目录上。所以：

- **更新插件不受影响**。换掉 custom_nodes 里的文件跟浏览器存储没有半点关系。
- **换成 localhost 打开就看不见了**。`127.0.0.1` 和 `localhost` 是两个不同的源。
- 清浏览器数据、磁盘紧张被驱逐、换浏览器、换机器 —— 都会没。

后三种只能靠导出兜底。它是唯一能跨源、跨机器、抗清缓存的方案。

**一、文件格式**

就一个对象：`app / kind / v / at / count / data`，外加可选的 `extra`。
`kind` 用来防串 —— 把 OC 的备份导进提示词页会当场被拒。
`extra` 目前只有提示词归纳用，装分类。

**二、合并优先，而且按名字去重，不按 id**

两个环境的 id 都是从 1 开始发的，按 id 去重一撞就会把用户真正想留的那条当成重复跳掉。
所以 id 一律丢掉让库重新分配，去重按名字。

**宁可重复也不许丢**：名字为空时不去重（判断写成 `if (k && seen[k])`，k 为空就放行）。
空名字要么是用户没填、要么是数据有问题，两种情况都不该被静默吃掉。

**三、分类得跟着卡片一起搬，而且 groupId 要重新对**

备份里的分类 id 和现在库里的 id 没有任何关系。`planGroups` 先算一份「旧 id → 新 id」的
映射（同名分类复用现有的，不新建重复的），`remapCards` 再按它把卡片上的 groupId 换掉。
**映射不到的一律当未分类** —— 宁可丢归属，也不能让卡片指着一个不存在的分类。

**四、持久化申请**

`navigator.storage.persist()` 在三个页面初始化时各调一次。授予之后浏览器在磁盘紧张时
不会自动驱逐这个源的数据。没授予不算失败，只是提示一句「记得导出备份」。

**五、实测**

真浏览器，同一份用户数据走完整链路：

- 建 2 张卡 + 1 个分类，导出成 634 字节的 json
- **换一个全新的 profile 打开**（等于换了源或换了机器）：卡片 0 张、空状态
- 合并导入：2 张卡 + 1 个分类全回来，**分类归属一字不差**（`仰拍构图[1]` / `伦勃朗光[0]`）
- 同一份再导一遍：**新增 0 张、跳过同名 2 张**，库里纹丝不动
- 改用替换导入：清空后正好剩 2 张，卡片的 groupId 正确重映射到新分类 id，
  未分类那张仍是 `[0]`
- 拿 OC 的备份往提示词页导：当场被拒

**这一轮的测试脚本自己错了两次**，都留了注释：等「列表里有卡」而不是等「多出来一张」，
导致第二张卡的名字覆盖了第一张；还有等状态文本「含导入完成」而不是「变了」，
于是读到的是上一次的结果。产品代码这两处都是对的。
